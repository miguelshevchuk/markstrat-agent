# Estrategia de I+D

## Principios clave

1. **Anticipar, no reaccionar.** Los proyectos tardan 1 período; planificar con anticipación
2. **Usar el Conjoint Analysis (Estudio 11)** para saber qué atributos importan más por segmento
3. **El base cost determina el margen.** Specs muy altas = costo alto = margen más bajo
4. **No mejorar todo a la vez.** Subir el atributo más valorado tiene más impacto que mejorar todo un poco

## Flujo de trabajo I+D

```
Período N:   Solicitar Conjoint Analysis (Estudio 11)
             Iniciar proyecto I+D con specs objetivo

Período N+1: Recibir resultados Conjoint
             Proyecto I+D completado → disponible para lanzar
             
Período N+2: Lanzar nueva marca / marca mejorada
```

## Naming convention

- Sonites: `P-[MARCA][VERSION]` → ej: P-TONIC2, P-TONE3
- Vodites: `P-[MARCA]` → ej: P-MELODY, P-MELODY2

## Rangos de atributos válidos

### Sonites
| Atributo | Mín | Máx | Unidad |
|----------|-----|-----|--------|
| Processing power | 5 | 100 | GFLOPS |
| Screen size | 4 | 40 | pulgadas |
| Design index | 3 | 10 | índice |
| Battery life | 24 | 96 | horas |
| Functions | 5 | 20 | cantidad |
| Base cost mínimo | $25 | — | USD |

### Vodites
| Atributo | Mín | Máx | Unidad |
|----------|-----|-----|--------|
| Resolution | 20 | 100 | L/mm |
| Energy efficiency | 10 | 100 | bC/Wh |
| Ecological impact | 5 | 50 | Kg |
| Connectivity | 3 | 10 | índice |
| Apps | 5 | 100 | cantidad |
| Base cost mínimo | $30 | — | USD |

## Checklist antes de enviar proyecto I+D

- [ ] Los specs están dentro de los rangos válidos
- [ ] El base cost resultante es aceptable para el precio target
- [ ] El nombre del proyecto no repite uno ya existente
- [ ] Hay presupuesto I+D asignado para este período
- [ ] El lanzamiento planificado tiene sentido con el mercado proyectado
